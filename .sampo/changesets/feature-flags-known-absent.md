Add the opt-in `feature_flags_known_absent` suite for adapters that declare both `feature_flags_local_evaluation_v1` and `feature_flags_known_absent_v1`. `/get_feature_flag` gains optional `person_property_keys_known_absent`, `group_property_keys_known_absent` and `allow_remote_fallback` params, sent only when a test sets them. `allow_remote_fallback: true` selects the SDK's default local-then-`/flags` getter. The suite checks local results for listed keys (`is_not_set`, `is_set`, a listed key overriding a supplied value, and an operator table) with no `/flags` request, and resolves a listed person key and a listed group key locally through the default getter. It also checks that the SDK falls back to `/flags` for a group key listed under another group type, for an unlisted omitted key, and for a listed key used by an operator the SDK doesn't implement locally (`not_between` in a dynamic-cohort leaf). The `/flags` fallback body must carry the listed keys, and a field must be omitted or null when nothing is listed for it, including when the caller passes an empty list or map. Adds the `assert_flags_request_field_absent` assertion.
