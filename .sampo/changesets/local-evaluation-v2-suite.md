Add the opt-in `feature_flags_local_evaluation_v2` suite for adapters that declare both `feature_flags_local_evaluation_v1` and `feature_flags_local_evaluation_v2`: the SDK requests the definitions feed with `v=2` and evaluates config version 2 flags locally. The suite reads the feature flag rules v2 contract. It serves the mixed definitions feed, checks that every definitions request carries exactly one `v=2`, also on a reload that sends the feed's ETag and gets 304, and checks the local value, payload and events of every supported entry, a per-flag `/flags` fallback in auto mode and no value in local-only mode for each unsupported entry, with siblings unchanged. It also runs every case of the boolean, value, experiment and local corpora that a black-box SDK can run, through `rules/local_outcomes.json`: a conclusive case returns its value locally and sends `$feature_flag_called` (and `$experiment_exposure` for a split) with `locally_evaluated` true, and an inconclusive case falls back or has no value. The definitions mock now serves a separate document to a request with exactly one `v=2`, records every query value, and supports an ETag and 304 per document. The Gherkin runner binds the sdk-specs #244 steps `the definitions service serves this typed document for v=2 requests:`, `the SDK is initialized for native local evaluation with remote fallback and JSON arguments:`, `every flag definitions request query parameter "v" should equal "2"` and `no received event named "<name>" should have property "<property>"`, plus a reload answered with 304 and an `If-None-Match` check.
